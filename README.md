# AI 동향 모니터 — 연구 축 고도화판 (중간과제 · 이유경)

팀 도구 [LoveEvaLee/ai-trend-monitor](https://github.com/LoveEvaLee/ai-trend-monitor)를
제 연구(조직 AI 수용 · 데이터/AI 거버넌스 · LLM 분류/오류 예측 등)에 맞게 개인적으로 고도화한
저장소입니다. 팀 공동 작업의 마지막 병합(`49d878c`)을 `midterm-start` 태그로 박고, 그 위에
판단 기준과 화면을 바꿨습니다. 여전히 **서버 없음 · 도구 안 AI 호출 없음 · 같은 입력이면 같은
결과**인 정적 페이지입니다.

- **고도화 전후 비교**: https://github.com/LoveEvaLee/ai-trend-monitor-evalee/compare/midterm-start...main

## 무엇을 고쳤나 (midterm-start 이후)

같은 입력 210건(제 수집물)에서 **미분류 106건(50%) → 71건(34%)**, 등급표 미등록 출처 54 → 37,
A등급 55 → 60. 수치의 근거는 [data/expected.md](data/expected.md)에 있습니다.

1. **주제 사전을 공용 KB에서 자동 생성** — 팀 주제 5개(과학기술정책 일반)를 제 연구 축 8개로
   바꿨습니다. 축과 키워드는 코드가 아니라 제가 매일 쓰는 관심 키워드 문서(옵시디언
   `키워드설정.md`)에 살고, `scripts/sync_topics.py`가 rules.js의 topics 블록을 재생성합니다.
   KB에서 그룹을 끄면(수요예측이 그 상태) 대시보드 주제도 함께 빠집니다.
2. **출처 등급표 보강** — 제 수집물에 나오는 DOI 발행처 7종·도메인 7종을 근거와 함께
   추가했습니다(확인된 것만 — 무명 학술지는 미등록 C로 남겨 보강 후보에 둡니다).
3. **판단 기준 추가** — 출처 유형 묶음(`sourceKinds`: 논문·공공기관·언론·코드모델·기업·
   전문가커뮤니티), '먼저 읽을 것'에서 언론 제외(`readExcludeKinds`), 특이 키워드의 불용어·
   희소성 가중(`distinct`), 별표 취향 보정의 공식과 상한(`personal`). 전부 rules.js에 있습니다.
4. **화면 전면 개편** (`js/view.js`) — 아래 "무엇을 보여 주나".

## 무엇을 보여 주나

| 화면 | 내용 |
|---|---|
| 요약 문단 | 수집 파이프라인 큐레이터의 주간 메모(`data/weekly_note.md`). 없으면 규칙 기반 자동 요약 |
| 지난주와 달라진 것 | 처음 등장한 키워드 · 급증/급감 축 · 처음 보는 출처 · 이번 주 A급 — 전부 규칙 계산 |
| 주제별 이번 주 흐름 | 연구 축 8장 카드. **카드를 누르면 아래 전체가 그 축 기준으로 바뀝니다**(크로스필터) |
| 먼저 읽을 것 | 축마다 중요도 1위 1건(언론·읽음 제외). 출처 유형 필터 · ☆ 별표 모아 보기 |
| 깔아볼 것 | 깃허브·허깅페이스 설치형 중 인기(★/♥ 실지표) 상위 3 · 최근 급상승 탭 |
| 특이 키워드 · 연결망 | 빈도 × 희소성 순위와 동시 등장 그래프 — 흔한 말은 가라앉습니다 |
| 읽음 ✓ · 별표 ★ | 읽으면 다음 후보가 올라오고, 별표가 쌓이면 추천이 취향 쪽으로 기움(배지로 이유 표시). 이 브라우저에만 저장 |
| 지난 호 보기 | `scripts/archive_issue.py`가 보관한 주간 호를 골라 그 주 화면을 재현 |
| 제목 마우스오버 | 이 글이 나에게 왜 필요한지 — 파이프라인이 공급한 요약(`note` 열), 없으면 규칙 기반 문구 |

## 사용법

1. 배포 주소를 열면 `data/latest.csv`(제 수집물)를 자동으로 읽어 바로 대시보드가 됩니다.
2. 직접 넣으려면 "입력"을 펼쳐 CSV를 붙여 넣거나 파일을 고릅니다.
   형식은 `date,title,url,source`(+선택 열 `note`), 날짜는 `YYYY-MM-DD`, UTF-8.
3. 결과는 CSV(다시 넣으면 같은 결과)와 마크다운으로 내보냅니다.

데이터 공급 파일(없어도 동작): `data/latest.csv` · `data/weekly_note.md`(큐레이터 메모) ·
`data/popularity.json`(깃허브 ★·HF 좋아요) · `data/archive/`(주간 호). 매일 수집
파이프라인(헤르메스·아르고스)이 자동 갱신합니다 — `scripts/export_monitor.py`가 digest를
공급 파일로 바꾸고, `scripts/vm_update.sh`(서버 크론, 매일 13:30)가 push까지 합니다.
호 보관은 월요일마다 한 번. 손으로 갱신하려면 `python3 scripts/export_monitor.py` 한 줄.

## 판단 기준과 한계

판단 기준은 전부 [rules.js](rules.js) 한 파일입니다(주제 사전 블록은 KB에서 자동 생성 —
직접 고치지 말고 KB에서 고칩니다). 한계: 제목 키워드로만 갈라서 내용이 맞아도 제목에 신호가
없으면 미분류로 남습니다. 읽음·별표는 브라우저(localStorage)에만 저장돼 기기 간에 이어지지
않습니다. 연구 축 기준이라 일반 기사 입력(팀 예시 116건)에서는 미분류가 많은 것이 정상입니다.

팀 저장소 참조. 코드와 문서 작성에 Claude Code를 썼고, 판단과 확인은 사람이 했습니다.
